### ✗ РЕГРЕССИЯ: кабинет остался БЕЗ H1 вовсе (нашёл Рома 2026-08-25)

Рома: «why we lost css for h1 in this page?» — на `/ru/cabinet`. Снято запросом:
**`<h1>` на `/ru/cabinet` — 0**, на контрольной `/ru/company` — 1.

**Причина — мой признак, а не стили.** Чиня двойной H1 на главной, я написал условие
`typeof title === "string" ? <H1>{title}</H1> : title` и рассуждал так: узел приносит тот, кто рисует
свой заголовок сам. Это неправда. Узел приносит и ОСТРОВОК, отдающий голый текст: у кабинета
заголовок зависит от роли (`vip_user` → «клиента компании», иначе → «гостя компании»), и роль
известна только после гидратации. По типу значения два случая неразличимы, и кабинет потерял не
стили, а сам тег.

🔒 **ЗАКОН: признак различает НАМЕРЕНИЕ ВЫЗЫВАЮЩЕГО, а не тип значения.** Тип — это то, что можно
проверить; намерение — то, что нужно знать. Совпадение типа с намерением в одном известном случае не
делает его правилом. Заведён явный `titleAsIs`, его ставит фабрика ровно там, где задан свой
`renderTitle`, — то есть только главная.

**Цена ошибки:** страница без `h1` — это не косметика. Заголовок первого уровня читают поисковик и
экранный диктор; его отсутствие они не сообщают, а просто не находят структуру страницы.

**Счёт по этому файлу:** третье исправление подряд в примитиве шапки — двойной H1, потом отсутствие
H1. Оба раза я менял ОБЩИЙ примитив ради ОДНОЙ страницы и оба раза не проверил остальных
потребителей. Проверка стоила одной команды: `grep -rn "title={<" app`.
