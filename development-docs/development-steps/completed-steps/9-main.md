## Главное открытие: предпосылка задания не подтвердилась

Задание исходило из того, что «в меню могут остаться пункты, ведущие в 404», потому что меню гейтами
не проверяются. Проверка показала обратное: **удалять было нечего.**

Причина не в везении, а в устройстве: манифесты групп лежат ВНУТРИ папок разделов
(`blog/_data/group.ts`, `products/_data/group.ts`) и ушли вместе со страницами в шаге 8, а реестр ящика
я вычистил тем же заходом, что и сами маршруты. Ветки `nav` в `APP-CONFIG` нет вовсе.

🔒 **Это не «нечего было делать».** Предпосылку можно было проверить только обходом, и обход — и есть
работа этого шага. Отрицательный результат, доказанный двумя негативными контролями, стоит ровно
столько же, сколько положительный.

## Сборка: закрытие шага на боевом сервере, 2026-08-25

Рома дал слово. `===DEPLOY_OK=== bb3e579`.

### Слот сам GitHub НЕ подтягивает — поправка к моей же записи

В `current-steps` стояло «слот подтягивает GitHub сам». **Неверно.** Слот стоял на `8c7b731` —
коммите шага 3; шаги 7–9 до него не доехали. В шаге 4 правка приехала **доставкой файла**
(`copy.sh`), а не `pull`, и совпадение я принял за автоматику.

🔒 **И доставкой файлами удаления не переносятся вовсе:** `copy.sh` распаковывает пути в слот, он
ничего не стирает. После шага 8 слот обязан был именно ПОДТЯНУТЬ — иначе удалённые страницы остались
бы жить на сервере.

Тянул через `run.sh` — это документированный цикл `pull → edit → push → build`, и `run.sh` для того
и есть. **Конфиг владельца сохранён руками:** `PLATFORM-CONFIG/platform-config.json` (`{"developmentMode":
"classic"}`) отслеживается git, панель пишет в него на сервере, и `pull` его затёр бы. Снял резерв →
подтянул → вернул. Риск назван прямо в шаблоне (`nav-config.ts`), и он реален.

### Первая сборка упала — и вскрыла промах шага 8

`check:blocks-map` уронил сборку **на сервере**, оставаясь зелёным локально. Механизм: генератор
вшивает в JSON содержимое карточек `sections/blocks/*.md`; git на Windows выдаёт их с CRLF, и внутрь
строк JSON попадает ЭКРАНИРОВАННАЯ последовательность из двух символов.

✗ **Правка шага 8 промахнулась молча.** Скрипт был написан строкой для оболочки: heredoc съел
обратные косые, счётчик считал экранированные последовательности, а замена била по настоящим байтам
концов строк. Файл выглядел исправленным — и был зелёным на Windows, красным на Linux.

**Как исправлено и чем доказано:** скрипт переписан ФАЙЛОМ, файл приведён к виду для Linux, и сумма
сверена с сервером:

```
сервер:  fff00bbde93fb025e16356fb8bc206f6ec04950b747c3c666e860ffc34963b3a  SECTIONS.json
локально: fff00bbde93fb025e16356fb8bc206f6ec04950b747c3c666e860ffc34963b3a
```

Совпало побайтово. 🔒 Локальный `check:blocks-map` на Windows отныне красен всегда — как
`check:config-schemas`; записано в `ANTI-PATTERNS` вместе со способом сверки через `sha256sum`.
