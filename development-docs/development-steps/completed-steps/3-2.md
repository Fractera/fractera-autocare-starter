# 3-2 — защищённая страница паспорта

**Закрыт 2026-08-24.** Второй подшаг шага 3. Первый код проекта.

## Триггер вида — назван до первой строки

**Страница** (свой адрес, ссылка из подвала) + **динамический виджет** (`_widgets/dynamic/passport-view`:
просыпается после гидратации и идёт за дверь). Не блок: паспорт — не содержимое каталожного вида, и
это то самое намеренное исключение из правила блоков, которое разрешено **только этой странице**.
Что увидит краулер без JavaScript: каркас без единой строки паспорта — и это не потеря, а требование;
защищённый слой объявлен `robots: { index: false }` своим макетом.

| Файл | Роль |

## Четыре решения, каждое — выбор среди существующего

**1. Содержимое едет из двери, а не из серверного компонента.** Прочитай файл каркас — паспорт
запёкся бы в предрендеренный HTML и достался бы любому, кто знает адрес. `AccessGate` — вывеска, её
выключают в том же браузере, где она нарисована. Это не осторожность, а прямое требование `use-roles`
§7: «загрузи страницу гостем и поищи в разметке данные — их там быть не должно».

**2. Вторая вывеска поверх групповой — сужение, а не дублирование.** Макет `(admin)` пускает `admin` и
`architect`; дверь пускает только `architect`. Без второй вывески администратор увидел бы страницу без
окна отказа и упёрся в пустоту с 403 в консоли — «доступ обещали и тут же отказали», дефект, уже
оплаченный на странице учётных записей (`use-roles` §3). Вывеска обязана повторять замок.

**3. Группу прав не заводил.** Пятая группа ради одного документа — изобретение там, где хватает
существующего: `architect` входит во все четыре по построению.

**4. `[lang]` в маршруте — потому что так говорит конфиг.** `NEXT_PUBLIC_SUPPORTED_LANGUAGES=en,ru`,
набор больше одного. Одноязычность исходника здесь ничего не решает, и вопрос «а нужен ли язык в
адресе» закрывается чтением конфига, а не рассуждением.

## Столкновение с законом — разведено, не обойдено молча

`use-roles` §6: «protected pages never appear in a public menu — a public button leading to a 403 is a
promise the site does not keep». Подвал — публичное меню, и решение Ромы «кнопка видна всегда» этому
формально противоречит.

Развёл так, как велел Рома: закон запрещает кнопку в **тупиковый** 403. Здесь тупика нет — страница
встречает объясняющим окном `AccessGate` с путём входа, то есть ровно тем знаком, который закон и
называет знаком. Постройка это обеспечивает: отказ объясняет причину и предлагает вход.

Кнопка стоит в **полосе действий**, рядом с архитектурой и панелью, а не в списке страниц подвала:
тот список владелец собирает в панели, и чужая строка в нём читалась бы как его забытая настройка.
Образец скопирован с уже стоявшей там ссылки на архитектуру — конструкция, ритм, поведение значка на
узком экране.

## Библиотека: почему `react-markdown` и что я для этого сделал

Рендерера markdown в проекте не было: `lib/aio/*` умеет обратное — блоки в markdown для машин. Свой
разборщик был бы изобретением, а паспорт наполовину состоит из таблиц, которых базовый markdown не
знает.

`react-markdown` **уже объявлен** в зависимостях — осознанный резерв владельца (`ANTI-PATTERNS`:
«Deleting dependencies that nothing imports»), и его прямое назначение — примеры возможностей.
`remark-gfm` физически лежал в `node_modules` **транзитивно**, через `streamdown`. Опираться на
транзитивную зависимость — тихая ловушка: пакет пропадёт при первом же обновлении соседа, и таблицы
молча станут текстом. Поэтому объявил его прямо: `npm install remark-gfm@^4.0.1`.

**Цена названа вслух:** `package.json` +1 строка, `package-lock.json` 2 строки, ни одного нового
скачивания — пакет уже был на диске. `streamdown` для этого не годился: он тянет `mermaid`, то есть
мегабайт в бандл защищённой страницы ради таблиц.

## Ошибки этого подшага

**Главная: первый тест доказал обход, а не замок.** Поднял дев-сервер, дёрнул `/api/passport` без
сессии и получил **200 с полным текстом паспорта**. Секунду выглядело как дыра в собственном коде.
На деле `shouldBypassAuth()` возвращает `true` **безусловно при `NODE_ENV=development`** — дев-сервер
выдаёт каждому роль `architect`. `use-roles` §5 называется ровно так: «the bypass, and why your test
may mean nothing», и я прочитал его до того, как писать код, — и всё равно поставил первый тест мимо.

**Привычка, которую фиксирую:** прежде чем измерять отказ, выясни, **кем тебя считает машина, на
которой ты меряешь**. Проверка права, поставленная на машине с обходом, зелёная всегда и не значит
ничего.

Обошёл так: ветка `x-agent-identity` в `getSession()` стоит **до** обхода и выдаёт роль `agent` — то
есть настоящую чужую роль. Через неё отказ по праву проверяется по-настоящему.

**Мельче:** первый `curl` по странице упал по таймауту в 20 с — Turbopack компилировал маршрут впервые.
Не дефект, но минута на догадки; в дев-сервере первый запрос к новому маршруту считать медленным.

## Доказательства — две плоскости, обе с негативным контролем

**Плоскость 1 — поведение двери (сеть).**

```
$ curl -s -i -H "x-agent-identity: probe" http://localhost:3000/api/passport | head -1
HTTP/1.1 403 Forbidden
$ curl -s -H "x-agent-identity: probe" http://localhost:3000/api/passport
{"error":"Forbidden","requires":["architect"]}
```

Что доказывает: сессия с чужой ролью получает **403, и отказ называет требуемую роль** — интерфейсу
есть что показать человеку.
Негативный контроль: тот же заголовок на двери, которая роль не спрашивает, —
`GET /api/health` → **200**. Значит 403 приходит от моего гейта, а не от заголовка, отвергнутого
где-то выше.
Как выглядело бы без изменения: 200 и текст паспорта, как в первом (ошибочном) замере.

**Плоскость 2 — содержимое разметки (что физически уезжает гостю).**

```
$ curl -s .../ru/administration/passport -o shell.html   # 200, 98 382 байта
Закон старта      0
ChatPush          0
YCLIENTS          0
светофор          0
со слов Филиппа   0
Мера успеха       0
```

Что доказывает: оболочка страницы **не несёт ни одной строки паспорта** — ровно то, чего требует
`use-roles` §7. Каркас предрендерен, текст приезжает только за роль.
Негативный контроль на том же файле: `Паспорт проекта` → 1, `administration/passport` → 1,
`Загружаю паспорт` → 1. Поиск работает по этому файлу и находит то, что там есть; значит шесть нулей —
это отсутствие текста, а не слепота инструмента.

**Дополнительно — кнопка и тема, обе проверены машиной, а не глазом:**

- кнопка в подвале **публичной** страницы: `href="/ru/administration/passport"` — 1 вхождение в
  `/ru`; негативный контроль — соседняя ссылка на архитектуру тоже 1;
- абсолютных цветов в новых файлах: **0** (`grep` на `#hex`, `rgb(`, `text|bg|border-<палитра>-<число>`);
  негативный контроль — тот же `grep` находит `bg-sky-600` и `bg-emerald-600` в `lib/flows.ts`, где
  абсолютные цвета законны. Использованы только токены: `bg-background`, `text-foreground`,
  `border-border`, `bg-muted`, `text-muted-foreground` — тема переключается сама.

**Гейты:** `check:types`, `check:i18n`, `check:api`, `check:protected`, `check:content`, `check:links`,
`check:menu`, `check:static`, `check:layout`, `check:seo`, `check:steps` — все зелёные. Сборка
доказательством не считается и в этот список идёт как гигиена, а не как приёмка.

## Чего я НЕ доказал — названо до слова «готово»

**Два из трёх ответов приёмки не проверены, и подменять их лёгкими я не буду:**

| Ответ | Состояние |
|---|---|
| чужая роль → 403 с названием роли | ✅ доказано выше |
| гость → 401 и путь входа | ⛔ **локально недоказуемо**: дев-сервер выдаёт всем `architect` (`shouldBypassAuth` при `NODE_ENV=development`) |
| архитектор → видит паспорт | ⛔ **локально недоказуемо**: нужна настоящая сессия службы `:3001` |

Обе проверки требуют **боевого сервера и сессии Ромы** — а сервер по границам шага не трогаю.
Проверяются одной командой каждая, когда Рома скажет разворачивать: `curl` без куки → ожидается 401;
вход владельцем → ожидается паспорт на экране и переключение темы на нём.
